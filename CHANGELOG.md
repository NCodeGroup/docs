## [Unreleased]

### Added

- A reusable workflow, `.github/workflows/site.yml`, builds a library's documentation site from the library's content folder and publishes it to that library's GitHub Pages from its default branch. A library calls it at one pinned commit and holds no npm manifest or lockfile. Its inputs are `content-path`, `deploy` and `toolchain-ref`, and its output is `page-url`. A pull request builds the site and keeps it as an artifact for a week ([ADR-1001](docs/decisions/1001-the-toolchain-lives-in-this-repository-and-a-library-calls-it-by-one-pinned-commit.md)).
- Sites are built with Astro Starlight and NCode's design system, Instrument, from NCode Brand 0.9.0: its tokens, fonts, mapping of Starlight's properties, code-block syntax theme and marks, vendored from the release, the toolchain's rules for Starlight's markup, the shared components `Status`, `Readout` and `Braces`, a search, and a 404 page. A library's own component styles itself with the brand's public tokens, prefixed `--nc-`. The toolchain's rules set each text in the brand's type role that names its use, running text in the `reading` role on the brand's measure, and read none of the brand's private primitives. The 404 page is the library's own `404.mdx` or `404.md`, or else the toolchain's, with the header's search box and a link to the site's start, and the build prints no warning about it ([ADR-1000](docs/decisions/1000-library-sites-are-built-with-astro-starlight-core-only.md), [ADR-1006](docs/decisions/1006-the-toolchain-renders-the-404-page-and-supplies-one-when-a-library-has-none.md), [#6](https://github.com/NCodeGroup/docs/issues/6), [#2](https://github.com/NCodeGroup/docs/issues/2), [ADR-1008](docs/decisions/1008-the-brand-is-vendored-from-an-attested-release-and-the-theme-restyles-only-starlights-markup.md)).
- `vendor/brand/` holds the files `vendor/brand/brand.lock.json` names from one release of NCodeGroup/brand, each pinned by its SHA-256: `npm run update:brand -- <version>` takes another release, and `npm run check:vendor`, which the tests run, fails with no network when a vendored file differs from the lock. Every day, the brand-watch workflow keeps one open issue labeled `brand-update` while NCodeGroup/brand has a release newer than the one the lock pins, with the release's links and the command that takes it, and closes it once the lock pins the newest release; `npm run watch:brand -- --dry-run` shows what it would do. The tests also fail when the theme, the code blocks or a component reads a custom property that neither the brand's stylesheets nor the theme define, or a step of the brand's colour ramps or type scale ([#2](https://github.com/NCodeGroup/docs/issues/2), [#26](https://github.com/NCodeGroup/docs/issues/26), [ADR-1008](docs/decisions/1008-the-brand-is-vendored-from-an-attested-release-and-the-theme-restyles-only-starlights-markup.md)).
- In a window narrower than 40rem (640 px), such as a phone's, a table written in Markdown is a stack of rows, each cell under its column's name, which the build copies from the table's head; a code listing wider than its screen lights each edge it has more code past, and its keyboard focus ring is drawn in the screen's lit colour just inside its edge, so no page scrolls sideways ([#3](https://github.com/NCodeGroup/docs/issues/3), [ADR-1007](docs/decisions/1007-a-markdown-table-stacks-on-a-phone-with-its-cells-labelled-when-the-site-is-built.md)).
- A library configures its site in `site.config.json`: title, description, repository, URL, navigation, mark, version label, links and sample globs. The file is checked against `schema/site.config.schema.json` before anything is built, and a wrong one stops the build with a message that names the key. A sample glob names files under the repository root: each file it matches is checked by its real path, with every symbolic link on its path followed, and one that a pattern or a symbolic link puts outside the repository stops the build too, as does a symbolic link that leads nowhere or around in a loop.
- A page includes a compiled sample by its key, `cs snippet=Key`, from a region of the library's tests marked `// begin-snippet: Key` and `// end-snippet`. An unknown key, a key defined twice, a region that is never closed, a malformed marker and a block with code of its own each stop the build ([ADR-1002](docs/decisions/1002-a-page-includes-a-compiled-sample-by-its-key-when-the-site-is-built.md)).
- An author writes links from the site's root, and the build adds the base path, so one page works under `/<repository>/` and at the root of a custom domain. A broken link, a relative link, a link written with the base path and a built page that links outside the base path each stop the build ([ADR-1003](docs/decisions/1003-links-are-written-from-the-site-root-and-the-build-proves-none-leaves-the-base-path.md)).
- C# 14 extension blocks are highlighted as declarations ([ADR-1004](docs/decisions/1004-the-csharp-grammar-is-patched-at-build-time-for-extension-blocks.md)).
- Each page links to its source in the library's repository and shows the date of the last commit that changed it. Where the library is in a repository whose history git cannot read, the pages show no date and the build warns, with git's message, as an annotation in GitHub Actions.
- `scripts/site.mjs` builds, serves or previews a library's site from a clone beside it: `npm run dev -- <library folder>` follows edits to pages and sample files, and writes nothing to the library.
- `CONTRACT.md` states what a library holds for its site and what the build does with it, and `fixture/` is a complete small library that the tests build.
- `docs/architecture.md` describes the toolchain's components and the rules its design keeps, and `docs/assurance-case.md` states its security requirements, its threat model and trust boundary, the check each input gets, the secure design principles it applies and the weaknesses it counters ([#13](https://github.com/NCodeGroup/docs/issues/13)).
- `GOVERNANCE.md` names the maintainer and owner, [@polewskm](https://github.com/polewskm), and says continuity stays incomplete until a second owner can administer the repository; `ROADMAP.md` states the plans for the next twelve months: keeping external inputs pinned and current, and reaching the OpenSSF Best Practices silver level ([#14](https://github.com/NCodeGroup/docs/issues/14)).
- CI checks the toolchain's code with Biome before it builds: `npm run lint` fails on a formatting difference in the JavaScript and TypeScript files and on a lint error or warning in them and in the Astro components, and `npm run format` applies Biome's formatting and safe fixes ([#10](https://github.com/NCodeGroup/docs/issues/10), [ADR-0201](docs/decisions/project-template/0201-biome-lints-and-formats-javascript-and-typescript.md), [ADR-1005](docs/decisions/1005-biome-lints-astro-components-without-formatting-them.md)).
- Each source file of the toolchain starts with a `Copyright © NCode Group` line and an `SPDX-License-Identifier: Apache-2.0` line: CI runs `./.template/Test-FileHeaders.ps1`, which fails a JavaScript or TypeScript file without them, and `-Fix` adds them; the Astro components, the stylesheet and `src/env.d.ts` carry them too, and `npm run test` fails one without them ([#12](https://github.com/NCodeGroup/docs/issues/12), [ADR-0027](docs/decisions/project-template/0027-source-files-carry-a-copyright-and-spdx-license-header.md)).

### Security

- The workflow's job that runs the site's packages and a library's pages has a read-only token. A second job, which checks out nothing and runs no code of the library or the toolchain, deploys, and only from the library's default branch ([ADR-1001](docs/decisions/1001-the-toolchain-lives-in-this-repository-and-a-library-calls-it-by-one-pinned-commit.md)).
- No job of the workflow restores or saves a cache, and every build is a full build.
- Packages are pinned to exact versions, each at least three days old when it is taken, and installed from the lockfile without install scripts. npm refuses a younger version with an `ETARGET` error, also with `--force`, and the README's development section says what that error means ([#5](https://github.com/NCodeGroup/docs/issues/5)).
- `npm run update:brand` writes a brand release's files only once `gh attestation verify` proves that NCodeGroup/brand's `publish.yml` built the release's archive for its tag on a GitHub-hosted runner, and the archive holds exactly the files its manifest lists, at their SHA-256 ([#2](https://github.com/NCodeGroup/docs/issues/2), [ADR-1008](docs/decisions/1008-the-brand-is-vendored-from-an-attested-release-and-the-theme-restyles-only-starlights-markup.md)).
- A built site loads its fonts, scripts and styles from its own origin.
- CI fails when the tests cover less than 90% of the statements or 80% of the branches of the toolchain's code, which `npm run test` measures and `./.template/Test-Coverage.ps1` checks, so a release is tagged only once that check passes again on its commit ([#11](https://github.com/NCodeGroup/docs/issues/11), [ADR-0026](docs/decisions/project-template/0026-tests-gate-coverage-at-the-gold-thresholds-and-a-release-waits-for-them.md)).
- A release is tagged only once CI passes again on its commit, and in this public repository its tag is signed with gitsign through Sigstore's keyless signing. Releases are immutable, and `SECURITY.md` says how to verify a release and its tag ([#7](https://github.com/NCodeGroup/docs/issues/7), [ADR-0026](docs/decisions/project-template/0026-tests-gate-coverage-at-the-gold-thresholds-and-a-release-waits-for-them.md), [ADR-0028](docs/decisions/project-template/0028-github-releases-are-immutable-and-their-tags-signed.md)).
- NCode Review approves a pull request whose review leaves no blocker or should-fix finding open, and a push dismisses that approval ([#7](https://github.com/NCodeGroup/docs/issues/7), [ADR-0022](docs/decisions/project-template/0022-ncode-reviews-approval-gates-the-merge.md)).
